# АО "Хиагда"

Веб-приложение для учёта номерного фонда вахтовых гостиниц.

## Архитектура

- **Frontend:** Vue 3 + Vite + Vue Router + Pinia (`web/`). Сборка отдаётся бэкендом.
- **Backend:** Node.js + Express + SQLite (`better-sqlite3`), JWT-авторизация (`server/`).
- **Один сервер:** Express раздаёт собранный фронтенд (`dist/`) и API (`/api`).
- Тема и токены оформления — Noctrinth/Modrinth (тёмная / светлая).

## Роли и порталы

| Роль | Портал | Права |
| --- | --- | --- |
| **Администратор** | `/app` | Полный доступ + пользователи + журнал действий |
| **Редактор** | `/app` | Гостиницы, номера, брони, проживающие |
| **Просмотр** | `/app` | Только просмотр календаря броней и отчётов |
| **Ремонтная служба** | `/app` | Заявки жильцов и вывод номеров на ремонт (без броней и номерного фонда) |
| **Вахтовик** | `/me` | Свой номер, соседи, дом и посёлок, заявки, отзывы (только своё) |

Аккаунты вахтовиков создаёт администратор в разделе **Пользователи** (роль «Вахтовик» + привязка к карточке проживающего). Войдя, вахтовик видит только свой кабинет; служебные эндпоинты для него закрыты.


## Возможности

**Персонал:** дашборд · **календарь броней** (протяжка — новая бронь, перетаскивание ленты — перенос на другое место, края — продлить, правый клик — меню, горячие клавиши по «?») · **план этажа** — настоящая схема здания с конструктором (номера + коридоры, лестницы, душевые, выходы; режим «вырезать клетки» даёт углы, впадины и Г-образные комнаты) · карта посёлков с числом свободных мест на метке · гостиницы и номера · справочники с подсчётом использования · история размещений · отчёты в Excel по номеру и человеку · импорт из Excel · журнал действий.

**Вахтовик** (5 вкладок): **Главная** — где живу, сколько дней до выезда, телефон коменданта, время выезда, объявления, мои заявки · **Мой номер** — паспорт номера, удобства (тап по сломанному = заявка), соседи, отзыв о номере · **Дом** — контакты, распорядок, правила, карта посёлка с точками рядом, отзыв о доме · **Заявки** · **Профиль**.

Вахтовику также доступен **план своего этажа** («вы здесь», где душевая, кухня, выход).

Отзывы раздельные: **о номере** (что чинить) и **о доме** (бытовые условия) — рейтинги не смешиваются.

## Запуск

Нужен [Node.js](https://nodejs.org/) LTS (18+).

```bash
npm install        # зависимости (бэкенд + фронтенд)
npm run seed       # БД, статусы, классы, удобства, демо-гостиница и демо-вахтовик
npm run build      # собрать фронтенд в dist/
npm start          # сервер → http://localhost:3000
```

При первом входе откроется форма **«Создать администратора»**. Демо-вахтовик из сидов: логин `vahta`, пароль `vahta`.

### Разработка (с горячей перезагрузкой)

```bash
npm run dev        # Express (:3000) + Vite (:5173) одновременно
```

Открывать `http://localhost:5173` — Vite проксирует `/api` на бэкенд.

### Тесты

```bash
npm test           # интеграционные тесты (брони, перенос, права ролей, план этажа) на временной БД
```

## Продакшен / размещение на сервере

1. Задайте окружение (см. `.env.example`): скопируйте в `.env`, пропишите **свой** `JWT_SECRET`.
   Без него секрет сгенерируется автоматически и сохранится в `data/.jwtsecret`.
2. Соберите фронтенд и запустите один процесс Node — он раздаёт и API, и `dist/`:

   ```bash
   npm ci --omit=dev && npm run build
   JWT_SECRET=... PORT=3000 npm start
   ```

3. Держите процесс живым менеджером (например `pm2 start server/index.js --name nochotel`
   или unit systemd) и поставьте перед ним reverse-proxy (nginx) с HTTPS.
4. **Бэкап:** вся база — это файл `data/nochotel.db` (+ `-wal`/`-shm`). Копируйте его по расписанию.
   Путь можно вынести на отдельный диск через `NOCHOTEL_DB`.

## Схема БД

`users(resident_id, role) · residents(about, photo) · hotels(settlement, address, phone, rules) · rooms(plan_x, plan_y, plan_w, plan_h) · beds · placements(stage) · statuses · room_classes · amenities · room_amenities · hotel_amenities · places · plan_shapes · reviews(room_id) · room_issues · room_blocks · announcements · audit_log`

Роли: `admin` / `editor` / `observer` (просмотр) / `maintenance` (ремонтная служба) — персонал; `viewer` — вахтовик (привязан к `residents` через `users.resident_id`).
`maintenance` в иерархию прав не встроен: по номерному фонду и броням он на уровне наблюдателя, но обслуживает заявки и `room_blocks` (проверка `requireRepair`).
`reviews.room_id`: `NULL` — отзыв о доме, иначе — о конкретном номере.
План этажа: `rooms.plan_x/y/w/h` — габарит в клетках сетки (`NULL` = не размещён), `plan_shapes` — коридоры, лестницы, санузлы и прочие помещения.
Форма: `rooms.plan_cells` / `plan_shapes.cells` — маска занятых клеток внутри габарита, по строке на ряд (`"111/100"` — Г-образная комната). `NULL` = обычный прямоугольник.

**Статусы делятся на два вида** (`statuses.kind`):

- `booking` — назначаются человеку при заселении (Забронировано, Проживает, любые свои). Только они видны в форме брони.
- `system` — производные состояния, их никому не назначают, они задают только цвет:
  `code='free'` — место свободно (это просто отсутствие брони), `code='repair'` — номер на ремонте.

Ремонт — это `room_blocks` (весь номер на период), а не бронь: профиль проживающего для него не нужен.
В календаре броней протяжка по пустым клеткам предлагает выбор «заселить» / «на ремонт», клик по полосе ремонта снимает его.
Системные состояния нельзя удалить и нельзя поставить брони — можно менять их название и цвет.

Чтобы начать с чистого листа — остановите сервер, удалите папку `data/`, затем `npm run seed`.
