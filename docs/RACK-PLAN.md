# План переработки шахматки (Rack)

Цель: превратить «таблицу с крашеными клетками» в нормальный tape-chart уровня БИТ:Отель /
QloApps: непрерывные ленты броней, полудни заезда/выезда, поповер с быстрыми действиями,
выделение периода мышью, ремонт на сетке, сводка свободных мест по дням.

---

## 1. Диагноз — что не так сейчас (`web/src/pages/staff/Rack.vue`)

### Логика и данные
1. **Баг на сервере: отменённые брони блокируют койку.** `findConflict` в `server/index.js`
   не фильтрует `stage <> 'cancelled'`. Фронт отменённые скрывает (клетка выглядит свободной),
   но POST вернёт 409 «Место занято» — призрак, которого не видно и не убрать без журнала.
2. **Нет ротации «день в день».** Конфликт считается по включительным датам
   (`date_from <= to AND date_to >= from`): выезд 15-го блокирует заезд 15-го. Для вахты
   пересменка в один день — основной сценарий; сейчас он невозможен.
3. **Ремонт (`room_blocks`) на шахматке не виден вообще.** Блокировки есть в Plan и
   в availability, а на главном инструменте планирования — нет. Можно заселить в номер,
   который на ремонте, и узнать об этом позже.
4. **Три запроса на загрузку** (`/rooms`, `/placements`, ещё `/hotels`+`/statuses` на маунте)
   и фильтрация placements по койкам на клиенте.

### Производительность
5. **`cellFor()` — это `Array.find` по всем placements на каждую клетку, по 4 раза**
   (`:class`, `:style`, `:title`, `@click` + `startName`). 30 дней × 40 коек × 4–5 вызовов —
   сотни тысяч сравнений на каждый рендер (а рендер дёргается любым ref'ом).

### Визуал
6. **Имя гостя не лента, а хак**: absolute-спан в первой клетке, вылезающий на соседние.
   Не обрезается по длине брони, наезжает на следующую бронь.
7. **Цвет текста на ленте захардкожен `#04150b`** — на тёмных статусах (серый «Свободно»
   `#3a3f47`) текст нечитаем. Контраст не вычисляется.
8. **Стадии не различимы.** «Ожидается» и «Проживает» — одинаковая заливка цветом статуса.
   Бронь и фактическое проживание на сетке выглядят идентично.
9. **Шапка с датами не sticky по вертикали** — при прокрутке вниз даты уезжают. Sticky
   есть только у левой колонки.
10. **Строка-заголовок номера** (`room-row` на всю ширину) ест высоту: на 10 номеров —
    10 пустых строк, полезная плотность падает вдвое.
11. **Нет строки месяца** — видно «пн 30, вт 31, ср 1…», а какой месяц у «1» — угадывай.
12. **Нет линии «сегодня»** через сетку (только подсветка в шапке), нет сводки
    «свободно мест по дням».
13. **Tooltip — нативный `title`**: медленный, без деталей, без действий.

### Взаимодействие
14. Клик по клетке открывает модалку **на один день** — забронировать «с 5-го по 12-е»
    мышью нельзя, даты вбиваются руками.
15. Быстрые операции («заселить», «выселить») требуют открытия модалки, хотя это
    один POST `/placements/:id/stage`.
16. «Загрузка…» текстом; при перелистывании весь grid мигает в пустоту.
17. Состояние (гостиница/дата/период) не в URL — F5 сбрасывает на сегодня.

## 2. Целевая картина

Сетка: слева sticky-колонка «№ номера (rowspan) · место», сверху sticky двухэтажная шапка
(месяц → день/день недели), справа-вниз — дни. Брони — **непрерывные ленты** поверх сетки:
скруглённые, с именем (обрезка ellipsis по ширине ленты), цвет = статус из БД,
паттерн = стадия. Заезд начинается с **середины** клетки дня заезда, выезд кончается
серединой дня выезда → в одной клетке видно пересменку: один выезжает, другой заезжает.
Ремонт — серая штрихованная лента на всю группу коек номера. Под шапкой — строка
«свободно мест» на каждый день. Hover по ленте — карточка-поповер с деталями и кнопками
стадий. Перетаскивание по пустым клеткам — выделение периода → модалка с датами.
Перетаскивание за шапку/ленты/фон — панорамирование (как сейчас).

## 3. Архитектура рендера (ядро переработки)

### 3.1 Один агрегирующий эндпоинт
`GET /rack?hotel_id&from&to` → `{ rooms: [{id, number, class_name, beds:[{id,label}]}],
placements: [...], blocks: [{room_id, date_from, date_to, reason}] }`.
Один round-trip вместо трёх, блокировки приходят сразу.

### 3.2 Предвычисленная раскладка вместо `cellFor`
Один `computed` строит за O(placements):
```js
layout = Map<bedId, Array<{p, startIdx, endIdx}>>   // индексы дней, клипнутые к окну
blocksByRoom = Map<roomId, Array<{b, startIdx, endIdx}>>
freePerDay = Array<число свободных коек на каждый день>  // с учётом блокировок
```
Клетки `<td>` становятся **пустым фоном** (weekend/today классы и клик по свободному дню).
Никаких вызовов функций в шаблоне клетки.

### 3.3 Ленты как позиционированный слой
Строка койки — `position: relative`; ленты — абсолютные `div.ribbon`:
```
left  = (startIdx + 0.5) * var(--rack-col)   // полдень заезда
width = (endIdx - startIdx) * var(--rack-col) // до полудня выезда
```
Ширина колонки — CSS-переменная `--rack-col: 38px` (легко сделать зум-контрол потом).
Лента: `border-radius: 999px`, имя внутри с `overflow: hidden; text-overflow: ellipsis`,
цвет текста вычисляется по яркости фона (та же формула, что для чипов статуса —
вынести хелпер `contrastText(hex)` в `@/ui` или utils).

**Паттерны стадий** (легенда обновляется):
- `expected` — полосатая заливка (`repeating-linear-gradient` 45°, цвет статуса + прозрачность);
- `checked_in` — сплошная;
- `checked_out` — сплошная с opacity 0.45;
- `cancelled` — не рендерится (и не конфликтует — после фикса сервера);
- блокировка — серая штриховка на всю высоту всех коек номера, поверх текст причины.

### 3.4 Компактная левая колонка
Вместо строки-заголовка номера: первая ячейка номера с `rowspan = beds.length`
(«№ 002», под ним класс мелким), рядом узкая подколонка мест («1», «2», …).
Плотность ×2, номер всегда виден слева от своих коек.

### 3.5 Sticky по обеим осям
`thead th { position: sticky; top: 0 }` (месяц `top: 0`, дни `top: <высота месяца>`),
угловая ячейка — sticky и left и top (z-index выше). Строка «свободно мест» — sticky
сразу под шапкой. Левая колонка — как сейчас sticky left.

## 4. Серверные правки

1. **`findConflict`**: добавить `AND p.stage <> 'cancelled'` (фикс бага) и перейти на
   строгие сравнения `p.date_from < ? AND p.date_to > ?` — день выезда свободен для нового
   заезда (пересменка). Семантика данных не меняется (`date_to` = день выезда, человек
   считается проживающим в этот день) — меняется только правило пересечения.
2. **`GET /availability`** привести к тому же правилу (свободна койка, если чужая бронь
   кончается в день искомого заезда) — иначе шахматка и поиск мест будут спорить.
3. **`GET /rack`** — агрегат из 3.1 (rooms + placements окна + blocks окна).
4. `POST /placements` дополнительно валидировать **пересечение с room_blocks**
   (сейчас можно заселить в заблокированный номер) → 409 «Номер на ремонте до …».

## 5. Взаимодействия

### 5.1 Мышь: правила разрешения drag-конфликта
Сейчас весь drag — панорамирование. Новое разделение:
- **drag с пустой клетки** → выделение периода в пределах этой койки (подсветка
  brand-рамкой), mouseup → PlacementModal с `date`/`dateTo` (пропсы уже есть);
  выделение клипается о соседние ленты (нельзя протянуть сквозь занятое);
- **drag с ленты, шапки, левой колонки, фона** → панорамирование (как сейчас);
- **средняя кнопка** → всегда панорамирование;
- Esc — сброс выделения; во время выделения `dragMoved`-гвард не открывает модалку кликом.
- Touch не перехватываем: на планшете нативный скролл, выделение — только мышью.

### 5.2 Поповер ленты (hover, ~150мс задержка)
Карточка: имя (клик → профиль в «Профилях»), даты + количество ночей, статус-чип,
стадия, комментарий, кнопки: **Заселить** (expected→checked_in), **Выселить**
(checked_in→checked_out), **Отменить** (danger, через ConfirmDialog), **Открыть** (модалка).
Кнопки бьют в существующий `POST /placements/:id/stage` и обновляют только этот placement
локально (без полного reload). Реализация — не kit-Popover (он для инлайна), а один
абсолютный элемент на страницу, позиционируемый от ленты (флип у краёв экрана).

### 5.3 Тулбар
- Кнопка **«Сегодня»** (сброс `from` на сегодня);
- шаги **«‹ неделя / неделя ›»** вместо прыжка на весь span (плюс сохранить прыжок
  по клику с Shift);
- период: 7/14/**30**/60 (60 — две вахты 30/30);
- фильтр класса — как есть;
- состояние `hotel_id`, `from`, `span` — в query-параметры URL (восстановление после F5,
  ссылку можно скинуть коллеге).

### 5.4 Клик по свободной клетке
Как сейчас — модалка на 1 день (drag не обязателен для короткого действия).

## 6. Мелочи (обязательный чеклист)

- [ ] Строка **месяца** над днями (colspan по фактическим границам), «Июль 2026»;
      на границе месяца — утолщённая левая граница колонки.
- [ ] **Линия «сегодня»**: вертикальная brand-линия через всю сетку (абсолютный div
      в слое лент), а не только подсветка шапки.
- [ ] **Строка «свободно»** под шапкой: число свободных коек на день; 0 — красным,
      ≤20% — оранжевым; учитывает блокировки.
- [ ] **Контраст текста лент** по яркости фона (никаких фиксированных `#04150b`).
- [ ] Выходные — текущее затемнение фона клеток + приглушённый день в шапке (есть).
- [ ] **Skeleton** при первой загрузке; при перелистывании — старый grid остаётся
      с `opacity: .5` до прихода данных (не мигает в пустоту).
- [ ] EmptyState: в гостинице нет номеров → иконка + кнопка «Добавить номер» (→ /app/hotels).
- [ ] Легенда: статусы из БД (как есть) **+ образцы стадий** (полосатая/сплошная/бледная)
      и образец штриховки ремонта.
- [ ] Поповер закрывается по Esc и уходу мыши; не всплывает во время drag.
- [ ] У ленты `min-width` полклетки — однодневная бронь всё ещё видна и кликабельна.
- [ ] Двойной клик по имени номера в левой колонке → drawer номера в /app/hotels
      (роут с query `?room=id`) — опционально, если быстро.
- [ ] `title` у дней в шапке — полная дата («вт, 15 июля 2026»).
- [ ] Часовые пояса: все даты остаются строками `YYYY-MM-DD`, никакого `toISOString()`
      для «сегодня» (в коде уже есть локальный формтер — использовать его везде,
      сейчас `dayLabel` сравнивает с UTC-`toISOString` — на +9 (Чита!) «сегодня»
      подсвечивается неправильно до 09:00 утра). **Это баг, чинится в первую очередь.**
- [ ] Правая граница окна: лента, уходящая за окно, обрезается без скругления
      (визуальный намёк «продолжается») — скругление только на реальных краях брони.

## 7. Этапы работ

**Этап 1 — данные и ядро рендера.**
Сервер: фикс `findConflict` (cancelled + строгое сравнение), тот же фикс в availability,
валидация блокировок, `GET /rack`. Фронт: layout-computed, ленты-слой, полудни,
rowspan-колонка, sticky-шапка с месяцем, линия «сегодня», фикс UTC-«сегодня»,
контраст текста, паттерны стадий, штриховка ремонта, строка «свободно». Это один большой
атомарный PR — шахматка меняется целиком.

**Этап 2 — взаимодействия.**
Drag-выделение периода (с правилами из 5.1), поповер с быстрыми действиями,
«Сегодня»/недельные шаги, URL-state, skeleton/непрозрачное перелистывание.

**Этап 3 — полировка по чеклисту** (всё, что не вошло в 1–2), прогон Definition of Done
из UI-REDESIGN §7.

**Не делаем (осознанно):** перетаскивание/растягивание существующих лент мышью
(move/resize) — красиво, но дорого и рискованно для учебных сроков, вся правка доступна
через модалку и поповер; виртуализация строк (до ~200 коек таблица держит);
бесконечная подгрузка дней при скролле (навигация кнопками/датой достаточна).

## 8. Критерий готовности

Комендант за 10 секунд отвечает на три вопроса, не открывая ничего:
«кто живёт в 002 и до какого числа» (лента с именем + поповер),
«куда заселить бригаду из 4 человек с 15-го на месяц» (строка «свободно» + пустые дорожки),
«что с номером 005» (штриховка ремонта видна прямо на сетке).
Пересменка «выезд и заезд 15-го» создаётся без ошибки 409 и читается в одной клетке.
