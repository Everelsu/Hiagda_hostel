# NochOtel — план переделки интерфейсов «с нуля»

Цель: заменить текущий «органически выросший» UI на систему, собранную из единого набора
компонентов. Переписываем **весь слой представления** (layouts, pages, разметку и стили),
**не трогая** сервер, API-клиент, роутер-карту и данные. Это и есть «с нуля» без риска
сломать работающую логику: каждая страница пересобирается атомарно, потому что API под ней
не меняется.

---

## 1. Диагноз: что не так с текущим UI

Честный список проблем, каждая — с примером из кода:

1. **Нет слоя компонентов.** Один и тот же «ряд списка» реализован 6+ раз под разными
   именами: `.urow` (Users), `.li` (RoomFund), `.irow` (Issues ×2), `.roommate` (Roommates),
   `.place` (Hotel), `.hotel-row` (Map). Копипаста стилей в каждом `<style scoped>`.
2. **Инлайн-стили повсюду.** `style="margin-top: 2px"`, `style="gap: var(--gap-sm)"` в
   каждом шаблоне. Отступы не системные, а «на глаз».
3. **Мега-модалка гостиницы** (RoomFund.vue): поля + карта-пикер + удобства + места +
   разделы + отзывы с ответами + фото — всё в одном скролле `Modal wide`. Это не модалка,
   это страница, притворяющаяся модалкой.
4. **RoomFund вообще перегружен**: 5 вкладок (гостиницы, номера, типы, статусы, удобства)
   на одной странице, редактирование всего — через модалки.
5. **Нет таблиц.** Журналы, проживающие, пользователи — div-списки без сортировки,
   пагинации и плотности. Для «рабочего» портала персонала это главный недобор.
6. **Браузерные `prompt()`/`confirm()`** для смены пароля и удалений (Users.vue,
   Residents.vue, RoomFund.vue) — системные диалоги ОС посреди тёмной темы.
7. **Обратная связь примитивная**: один вид тоста на всё (успех/ошибка неразличимы),
   ошибки форм не привязаны к полям.
8. **Загрузка = текст «Загрузка…»** на каждой странице, скелетонов нет. Пустые состояния
   оформлены по-разному (где-то иконка+текст, где-то просто muted-строка).
9. **Сайдбар персонала** — костыли: фильтр классов Rack зашит прямо в навигацию с
   хардкодом «Одноместный/Двухместный/Трёхместный» (не из API), а `auth`-стор используется
   как глобальная шина (`auth.roomClassFilter = ref("")`, `auth.newIssuesCount` присваиваются
   из layout'а). Инлайн-стили прямо в `<router-link>`.
10. **Мобильный портал персонала** фактически нерабочий: media-query просто сваливает
    сайдбар в переносимую строку ссылок.
11. **Доступность**: кнопки-иконки без `aria-label`, дефолтные фокус-обводки, контраст
    цветных чипов не проверен.
12. **Навигация внутри разделов** — рукописные `‹ Назад`, нет заголовков-хлебных крошек.
13. **Login** — голая карточка без композиции.

Что **хорошее** и остаётся: дизайн-токены Modrinth (`tokens.css`), иконки lucide
(`Icon.vue`), Leaflet-карта (`MapView.vue`), `Stars.vue`, `Gallery.vue`, API-клиент,
роутер-карта, вся серверная логика.

## 2. Принципы нового UI

1. **Ноль инлайн-стилей и ноль page-scoped копипасты.** Всё, что повторяется дважды, —
   компонент кита. Странице разрешён scoped-CSS только для уникальной сетки самой страницы.
2. **Два темпа, одна система.** Персонал: плотно, таблично, много на экран, drawer'ы для
   форм. Вахтовик: одна колонка, крупно, карточки. Оба собраны из одних компонентов
   с проп-вариантами (`density="compact|comfy"`).
3. **Цвет = статус, всегда из БД.** Палитра `statuses.color` и стадии — единственный
   источник цвета для шахматки, плана, карты, бейджей. Никаких новых хардкод-хексов
   в страницах (сейчас они разбросаны по Dashboard, Issues, Map).
4. **Формы**: ошибка у поля, а не только тостом; кнопка сабмита с busy-состоянием;
   деструктивные действия — только через `ConfirmDialog`.
5. **Каждый экран имеет три состояния из коробки**: skeleton (загрузка), empty
   (пусто, с иконкой и действием), error (с кнопкой «повторить»).
6. **Доступность как норма**: `aria-label` на иконочных кнопках, видимый focus-ring
   (токен `--focus-ring`), тач-цели ≥ 44px в кабинете вахтовика.

## 3. Архитектура: UI-кит `web/src/ui/`

Новый каталог — единственное место, где живут стили компонентов. `app.css` худеет до
reset + типографика; классы `.card/.btn/.chip/.field/.li` объявляются устаревшими и
удаляются в конце (этап D).

### 3.1 Примитивы
| Компонент | Заменяет | Ключевое |
| --- | --- | --- |
| `Button` | `.btn*` + инлайны | варианты primary/brand/ghost/danger, size sm/md/lg, `loading`, слот иконки |
| `IconButton` | кнопки-иконки | обязательный `label` (aria) |
| `Input`, `Textarea`, `Select` | голые теги | единые высоты, `invalid`-состояние |
| `Field` | `.field` | label + hint + error, привязка ошибки к полю |
| `Switch`, `Checkbox` | чекбокс приватности и пр. | |
| `SegmentedControl` | tab-bar RoomFund, фильтры статусов | |
| `Chip` / `Badge` | `.chip`, `.menu-issue-badge` | вариант со статус-цветом из БД |
| `Avatar` | 3 рукописных `.avatar` | фото/инициалы, размеры |
| `Card` | `.card` | + `CardHeader` со слотом действий |

### 3.2 Составные
| Компонент | Назначение |
| --- | --- |
| `PageHeader` | заголовок страницы: title + subtitle + actions + опц. «назад» (убирает рукописные `‹ Назад`) |
| `DataTable` | таблица персонала: колонки конфигом, сортировка, sticky-шапка, skeleton-строки, встроенный EmptyState, слот row-actions |
| `ListRow` | единый ряд списка (иконка/аватар + основной текст + вторичный + значение + действия) — для кабинета вахтовика и коротких списков |
| `Drawer` | боковая панель для форм и карточек (правая, 420–560px) — заменяет большинство модалок персонала |
| `Modal` | остаётся только для коротких диалогов (< 1 экрана) |
| `ConfirmDialog` / `promptDialog()` | замена `confirm()`/`prompt()`; программный вызов `await confirm({...})` |
| `Toast` v2 | варианты success/error/info, иконка, очередь |
| `EmptyState` | иконка + текст + опц. действие |
| `Skeleton` | text/row/card/table пресеты |
| `Stat` | KPI-плитка дашборда |
| `MeterBar` | полоса загрузки (дашборд, карта) |
| `Popover` | hover/click-поповеры (план этажа, карта, шахматка) |
| `Tabs` | вкладки страницы гостиницы |
| `FilterBar` | строка фильтров над таблицей (селекты + поиск + сброс) |
| `StatusDot` | точка статус-цвета — вместо 4 реализаций `.dot.lg` |

### 3.3 Токены — дополнить `tokens.css`
- `--focus-ring: 0 0 0 2px var(--color-bg), 0 0 0 4px var(--color-brand)`
- шкала z-index (`--z-drawer`, `--z-modal`, `--z-toast`)
- моушен: `--speed-fast: 100ms; --speed: 180ms` + `prefers-reduced-motion`
- контроль-высоты: `--control-h-sm/md/lg` (28/36/44px) — одна высота для input/select/button

## 4. Каркасы (shells)

### 4.1 StaffShell — новый каркас персонала
- **Сайдбар**: конфиг-массив (`nav.js`), а не рукописный список ссылок; группы
  «Основное / Общение / Номерной фонд / Администрирование»; бейджи объявляются в конфиге
  (счётчик заявок — из отдельного лёгкого стора `useCounters`, а не из auth).
  Сворачивается до иконок (state в localStorage).
- **Топбар**: заголовок текущей страницы (из route meta), глобальный поиск
  (`Ctrl+K` — проживающие/номера, живёт над существующими `/residents?q=` и `/rooms`),
  переключатель темы, меню пользователя (имя, роль, выход).
- **Мобайл**: сайдбар становится off-canvas drawer'ом по кнопке-бургеру — вместо
  нынешней «свалки ссылок».
- Фильтр классов **уезжает из сайдбара в тулбар шахматки** (FilterBar), классы берутся
  из `GET /classes`, хак с `auth.roomClassFilter` удаляется.

### 4.2 ResidentShell — полировка
Концепция (таб-бар снизу, верхняя навигация на десктопе) остаётся, но пересобирается на
ките: `Avatar` в шапке, унифицированные бейджи, `PageHeader` вместо рукописных `‹ Назад`,
safe-area уже есть. Добавить лёгкий переход между вкладками (fade 120ms).

## 5. Постраничный план — портал персонала

Порядок = приоритет.

1. **Login** — сплит-экран: слева брендовая панель (тёмный градиент, точка-логотип,
   подпись «Учёт номерного фонда вахтовых гостиниц»), справа форма на `Field`.
   Ошибка — под полем. Setup-режим (первый админ) — тот же экран с другим заголовком.
2. **Гостиницы: RoomFund → распад на два раздела.**
   - `/app/hotels` — список гостиниц (карточки с фото-обложкой, рейтингом, счётчиком
     номеров/мест) → **страница гостиницы** `/app/hotels/:id` с вкладками `Tabs`:
     *Обзор* (поля + карта-пикер), *Номера* (таблица номеров этого дома, редактирование
     в Drawer), *Что рядом*, *Разделы «О доме»*, *Фото*, *Отзывы* (с ответами).
     Мега-модалка умирает.
   - `/app/catalogs` — «Справочники»: типы, статусы, удобства (три простых списка).
3. **Шахматка (Rack)** — флагман, полирнуть: sticky и шапка дат, и колонка номеров;
   тулбар с FilterBar (дом, класс, период, «сегодня»); hover-поповер по ленте брони
   (кто, стадия, даты, кнопка «открыть»); клетки чуть выше, ленты с читаемым контрастом.
4. **Заявки** — таблица/список на `DataTable` + Drawer вместо модалки (тред просторнее),
   счётчики статусов как SegmentedControl-фильтр.
5. **Проживающие** — `DataTable` (ФИО, таб.№, организация, размещение, доступ) +
   Drawer-карточка с вкладками *Профиль / Размещения / Доступ*; выдача доступа и креды —
   через `ConfirmDialog`/собственный диалог, никаких `prompt()`.
6. **Дашборд** — `Stat`-плитки, `MeterBar` по гостиницам, тренд оставить самодельным
   (работает), но перевести цвета стадий на палитру из БД.
7. **Карта** — уже новая; заменить встроенный список на `ListRow`, легенду на `Chip`,
   попапы Leaflet → стилизованный `Popover`-шаблон с кнопками «Шахматка»/«План».
8. **План этажа** — hover-`Popover` по номеру (кто живёт, до какого числа, свободные
   койки, бейдж ремонта) — закрывает недоделанный пункт старого плана.
9. **Журналы (Journal, Movements, Audit)** — один шаблон: `FilterBar` + `DataTable`
   + пагинация; Movements — две таблицы (заезды/выезды) с датой в тулбаре.
10. **Пользователи** — `DataTable`, форма в Drawer, пароль через диалог.
11. **Объявления** — уже свежие; пересадить на кит (CardHeader, ConfirmDialog).

## 6. Постраничный план — кабинет вахтовика

Кабинет недавно переработан, поэтому здесь не редизайн, а **пересборка на ките + полировка**:

1. **Главная**: skeleton-карточки вместо «Загрузка…», `ListRow` для заявок,
   секции через `CardHeader`.
2. **Мой дом**: `PageHeader` с «назад», разделы-аккордеоны на мобильном (правила и
   длинные инфо-блоки сворачиваются), кнопка «позвонить коменданту» (`tel:`) в шапке.
3. **Соседи**: `ListRow` + `Avatar`; пустое состояние с иконкой.
4. **Заявки**: пересадить на кит; форма новой заявки — полноэкранный Drawer снизу
   (bottom-sheet) на мобильном.
5. **Профиль**: `Field` + `Switch` для приватности; загрузка фото с превью-кропом
   (просто квадратное превью, без реального кропа).
6. Единые скелетоны и переходы между вкладками.

## 7. UX-стандарты (Definition of Done для каждой страницы)

- [ ] Нет инлайн-стилей и локальных копий кит-паттернов
- [ ] Skeleton при загрузке, EmptyState при пустоте, error-состояние с retry
- [ ] Деструктивные действия — через ConfirmDialog с описанием последствий
- [ ] Ошибки форм привязаны к полям; submit disabled/busy
- [ ] Иконочные кнопки имеют aria-label; фокус-обводка видима
- [ ] Работает на 375px (вахтовик) / 1280px (персонал); staff-страницы живы на планшете
- [ ] Цвета статусов — только из БД/токенов, без новых хексов
- [ ] Тёмная и светлая темы проверены

## 8. Порядок работ и разделение на троих

**Этап A — фундамент (вместе, ~2–3 дня).**
Кит: примитивы + Drawer/ConfirmDialog/Toast v2/DataTable/EmptyState/Skeleton/PageHeader.
Дев-страница `/app/_kit` (только в dev-сборке) со всеми компонентами — живой каталог
вместо Storybook. Новые shells (Staff + Resident). Чистка auth-стора (счётчики → `useCounters`).

**Этап B — страницы персонала (параллельно).**
- **A (таблицы/данные):** Проживающие, Пользователи, Журналы ×3, Заявки.
- **B (гостиницы/гео):** Hotels-раздел (список + страница с вкладками), Справочники,
  Карта-полировка, План этажа с поповерами.
- **C (флагманы):** Login, Дашборд, Шахматка, Объявления.

**Этап C — кабинет вахтовика (один человек, пока двое добивают B).**
Пересборка 5 экранов на ките по разделу 6.

**Этап D — снос старья.**
Удалить из `app.css` компонентные классы, убрать мёртвые scoped-стили, грепнуть
`style="` по `pages/` (цель — ноль вхождений), прогнать чеклист раздела 7 по каждой
странице, обновить скриншоты в README.

Правило миграции: страница переключается на новый вид **целиком за один PR**; полстраницы
на ките, полстраницы на старых классах — запрещено. `/legacy` не трогаем.

## 9. Что явно НЕ делаем

- Не тащим UI-библиотеки (Vuetify/PrimeVue/Naive) — кит на токенах меньше и роднее,
  и это учебная ценность проекта.
- Не переезжаем на Tailwind — токены + компоненты уже дают систему.
- Не переписываем сервер и API-клиент.
- Не делаем реальный Storybook — хватает dev-страницы `/app/_kit`.
- Не выдумываем новую цветовую тему — палитра Modrinth остаётся фирменным лицом.
